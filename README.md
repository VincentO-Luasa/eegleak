# eegleak

[![CI](https://github.com/VincentO-Luasa/eegleak/actions/workflows/ci.yml/badge.svg)](https://github.com/VincentO-Luasa/eegleak/actions/workflows/ci.yml)

Catch data leakage in EEG train/validation/test splits, and run negative controls, before you trust a benchmark number.

## Why this exists

EEG datasets contain long recordings from a small number of people. If windows from the same person end up in both the training set and the test set, a model can learn to recognise the person instead of the thing you care about (a sleep stage, a seizure, a mental state). The test score then looks excellent, but the model fails on a new person. A second problem affects pretrained "foundation" models: the evaluation data can overlap with the data the model was pretrained on, which inflates results in the same way.

`eegleak` makes these problems easy to detect:

- it checks split metadata for subject, recording and time-window overlap,
- it flags duplicate windows and large shifts in class balance between splits,
- it warns when an evaluation dataset overlaps a known pretraining corpus,
- it measures how much a leaky split would have inflated your score,
- it runs a label-permutation control that should stay at chance if your pipeline is sound.

## Quick start

### Command line

Your splits file has one row per window (`start_s`, `end_s` and `label` are optional):

```csv
window_id,subject_id,recording_id,split,start_s,end_s,label
0,S01,S01-N1,train,0.0,30.0,N2
```

```bash
eegleak check examples/leaky_splits.csv
```

```
**Result: FAIL** (3 errors, 1 warnings)

| Severity | Check | Message |
|---|---|---|
| ERROR | subject_overlap | 2 subject(s) appear in more than one split: S03 (test, train), S05 (test, train). |
| ERROR | recording_overlap | 1 recording(s) appear in more than one split: S05-N1 (test, train). |
| ERROR | window_temporal_overlap | 1 window(s) in 1 recording(s) overlap in time with a window from another split: S05-N1. |
| WARN | label_shift | Class distributions differ between splits: total variation 0.3525 for test/val (threshold 0.1). |
```

The command exits with status 1 if any error is found (0 for `examples/clean_splits.csv`), so it can run in CI. Use `--format json` for the full details, `--gap-s 30` to also warn about windows from different splits that are less than 30 s apart, and `--subject-col` etc. for other column names. See `eegleak check --help`.

`examples/leaky_splits.csv` is generated by [`examples/make_examples.py`](examples/make_examples.py) and contains three planted problems: subject S03 has one night in train and one in test; recording S05-N1 was cut into train and test with 50%-overlapping windows; the test subjects are mostly awake.

### Python

```python
import pandas as pd
import eegleak

df = pd.read_csv("examples/leaky_splits.csv")
report = eegleak.run_metadata_checks(df)
print(report.ok)
print(report.errors[0].details["overlapping"])
```

```
False
{'S03': ['test', 'train'], 'S05': ['test', 'train']}
```

`report.to_markdown()` and `report.to_dict()` give the table above and a JSON-ready dict.

### Negative controls on a model

`X` has shape `(n_windows, ...)` (flattened internally); `y` and `groups` (e.g. subject IDs) have shape `(n_windows,)`. Any scikit-learn estimator works.

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
import eegleak

# 10 subjects x 20 windows. Each subject has a distinctive EEG "fingerprint";
# the label is a per-subject trait, so only identity predicts it.
rng = np.random.default_rng(0)
groups = np.repeat(np.arange(10), 20)
X = rng.normal(size=(10, 8))[groups] + 0.1 * rng.normal(size=(200, 8))
y = groups % 2
est = KNeighborsClassifier(n_neighbors=1)
print(eegleak.group_vs_random_gap(X, y, groups, est).message)

# Window-level labels that carry no signal: permuted labels must stay at chance.
y = rng.integers(0, 2, size=200)
print(eegleak.label_permutation_test(X, y, groups, est, n_permutations=50).message)
print(eegleak.pretraining_overlap(["TUAB", "Sleep-EDF"], "CBraMod").message)
```

```
A random split inflates the score by 0.500: random K-fold 1.000 vs group K-fold 0.500 (balanced accuracy, 5 folds).
Permuted labels give chance performance: permuted-label score 0.490 ± 0.026 vs chance 0.500; real score 0.479, p = 0.647 (50 permutations).
Possible pretraining overlap for CBraMod: TUAB is a subset of TUEG, which is in the pretraining corpus.
```

The p-value is `(1 + #null >= real) / (1 + n_permutations)`, so its resolution is `1 / (1 + n_permutations)`: use at least 99 permutations to be able to report p < 0.01.

## Checks

Every check returns a `Finding(check, severity, message, details)`. A passing check returns an `info` finding saying what was checked. A check that cannot run (missing column, single split, ...) returns a `warning` saying why, never a silent pass. A `Report` is `ok` when it has no errors.

| Check | Severity | What it catches |
|---|---|---|
| `subject_overlap` | error | A person appears in more than one split |
| `recording_overlap` | error | A recording appears in more than one split |
| `window_temporal_overlap` | error / warning | Windows from different splits overlap in time (error), or are less than `gap_s` apart (warning) |
| `duplicate_windows` | error | Identical windows (after rounding to `decimals`) in more than one split |
| `label_shift` | warning | Class distributions of two splits differ by total variation above `tv_threshold` |
| `pretraining_overlap` | warning | An evaluation dataset is in, or may overlap, a model's pretraining corpus ([sourced registry](src/eegleak/registry.py)) |
| `group_vs_random_gap` | warning | Random K-fold scores much higher than group K-fold |
| `label_permutation_test` | error | Performance stays above chance when labels are permuted within groups |
| `run_metadata_checks` | report | Runs the first two checks, plus the temporal and label checks when their columns exist |

The pretraining registry covers BIOT (three released checkpoints; `BIOT` means the six-dataset one), CBraMod, LaBraM and EEGPT. Each entry carries its source, and [`docs/NOTES.md`](docs/NOTES.md) records how each was verified.

## Limitations

`eegleak` cannot detect:

- leakage through preprocessing statistics (e.g. normalisation) computed on all data before splitting,
- label information hidden in the features,
- the same person recorded under different IDs,
- pretraining overlap for models or datasets that are not in the registry.

A passing report means the checks above found nothing, not that your evaluation is correct.
